## 🚦 MANDATORY: Test Before Deploying to Production

**NEVER push directly to `main` for non-trivial changes without testing first.**

### The Workflow:

```
Make changes
     ↓
Push to `staging` branch  →  Test at staging URL
     ↓ (passes? ✅)
Merge / push to `main`    →  Goes live at wylibrary.org
```

### Step-by-Step:

```bash
# 1. Switch to staging branch
git checkout staging

# 2. Merge your changes into staging
git merge main
# (or cherry-pick specific commits, or directly edit on staging)

# 3. Push to staging
git push origin staging

# 4. Wait ~60 seconds, then test at:
#    https://staging.wylibrary.pages.dev

# 5. Test thoroughly (see checklist below)

# 6. If all good, switch back to main and push
git checkout main
git merge staging
git push origin main
```

## ✅ Pre-Deploy Test Checklist

Before merging to `main`, verify the following at `https://staging.wylibrary.pages.dev`:

**Online behaviour:**
- [ ] Home page loads with all category cards and book counts
- [ ] Dark mode toggle works
- [ ] Search works inside a folder
- [ ] A PDF opens in the viewer
- [ ] Download button works on a file

**Offline behaviour (Chrome DevTools → Network → "Offline" or turn off Wi-Fi):**
- [ ] Page loads (no dinosaur / no blank white screen)
- [ ] Dark mode toggle still works
- [ ] Nav links (Home, Practice, About, Contact) render content
- [ ] Offline banner appears: `"📡 You are offline..."`
- [ ] Practice Quiz loads and questions can be answered
- [ ] Reconnecting shows `"🟢 Back online!"` and banner fades

**PWA:**
- [ ] Service Worker registers in DevTools → Application → Service Workers
- [ ] `wylibrary-v10-*` cache appears in DevTools → Application → Cache Storage

**After a code change (update test):**
- [ ] On a tab that was open before the push, the update toast appears: `"⚡ Update Available [Update]"`
- [ ] Clicking Update reloads and shows green: `"✅ Updated successfully to vX.X!"`

## 🏗️ Project Architecture

- **Host:** Cloudflare Pages (free tier) — auto-deploys on push to `main`
- **Storage:** Cloudflare R2 (two buckets)
  - `media1.wylibrary.org` — Books (PDFs)
  - `pub-de3a22d4e4324e8ba9a0690313176f71.r2.dev` — Exams / Zips / Q&A
- **Analytics:** Cloudflare Web Analytics (Automatic) + GA4 (`G-2SRWNGHTMS`)
- **PWA:** Service Worker at `/sw.js` — Network-First caching (v10+)
- **Cloudflare Account ID:** `c5703910f00b285b8660ec05372093f6`

## 📁 Key Files

| File | Purpose |
|---|---|
| `public/index.html` | Main app shell (HTML only — logic is in app.js) |
| `public/app.js` | All UI logic, routing, catalog, dark mode, SW registration |
| `public/sw.js` | Service Worker — caching strategy & offline mode |
| `public/_headers` | HTTP cache-control rules for Cloudflare CDN |
| `public/files-index.json` | Catalog of all R2 files (auto-generated by generate-index.js) |
| `public/quiz-data.json` | Practice quiz questions (offline-capable) |
| `public/styles/` | Modular CSS (base, layout, components, navigation, modals, practice, dark-mode) |
| `generate-index.js` | Script to regenerate files-index.json from R2 |
| `scripts/migrate_to_r2.py` | Uploads files to R2 |

## ⚠️ Constraints (Never Break These)

- **100% free infrastructure only** — no paid services
- **Mobile-first** — always test on mobile screen sizes (Samsung, Redmi A5)
- **Dark mode must remain intact** — never change dark theme styling unintentionally
- **`files-index.json` must exist in both root AND `public/`**
- **`generate-index.js` and `scripts/migrate_to_r2.py`** must both write to `public/files-index.json`

## 🔧 Useful Commands

```bash
# Regenerate the file catalog (after adding new R2 files)
node generate-index.js

# Upload files to R2
python3 scripts/migrate_to_r2.py

# Check Cloudflare Pages deployments
wrangler pages deployment list --project-name=wylibrary

# Manual one-off preview deploy (no git needed)
wrangler pages deploy public --project-name=wylibrary
```
